# Data

All data in this repository is **synthetic** — generated by
`backend/app/risk/generate.py` from the archetype-level score distributions
in `backend/app/risk/config.py`. No real facility, client, or incident data
is used anywhere in this project.

- `raw/` — reserved for future inputs (e.g. if reference figures are ever
  layered in); currently empty.
- `processed/facilities.csv` — the generated dataset. Committed (small,
  fully synthetic) so a fresh clone or a deploy doesn't need to regenerate
  it. Regenerate and commit the result with:

  ```bash
  cd backend
  uv run python -m app.risk
  ```

## Schema

One row per synthetic facility.

| Column | Type | Notes |
|---|---|---|
| `facility_id` | str | `F001`, `F002`, ... |
| `archetype` | str | one of the 4 archetype keys |
| `archetype_label` | str | human-readable archetype name |
| `asset_criticality` | float, 1-5 | raw factor score |
| `public_accessibility` | float, 1-5 | raw factor score |
| `perimeter_vulnerability` | float, 1-5 | raw factor score |
| `threat_exposure` | float, 1-5 | raw factor score |
| `existing_countermeasures` | float, 1-5 | raw factor score — **higher = stronger countermeasures** (inverted before weighting; see `app/risk/scoring.py`) |
| `site_complexity` | float, 1-5 | raw factor score |
| `response_readiness` | float, 1-5 | raw factor score, scored in risk polarity (higher = slower/worse response) |
| `risk_score` | float, 0-100 | weighted risk score, see `app/risk/scoring.py` |
| `cameras`, `access_control`, `guards`, `lighting`, `fencing` | bool | countermeasure flags, generated to correlate with `existing_countermeasures` |
| `incident_likelihood` | float, 0-100 | **fully synthetic simulated outcome**, not real incident data — see the EDA notebook, Section 8, for the exact generative formula |

Reproducible with a fixed seed (default `42`); regenerating with the same
seed and `n_per_archetype` reproduces this dataset exactly.
